# シェルの使い分け

ユーザーの対話シェルはfishだが、実装に使用するシェルがfishとは限らない。実行する場所・用途に応じて、以下を区別する。

## ユーザー向けの実行コマンド

- 「コマンドを書いて」など、ユーザーが対話シェルに貼り付けて実行するためのコマンドは、原則としてfish構文で提示する
- この用途ではbash固有構文を避け、bashでの実行が必須の場合はその理由と実行方法を明記する

## コード・スクリプト・設定ファイル

- ファイルに保存するコードや、回答中で示す実装例には、上記のfish指定を適用しない。コードブロックかどうかではなく、用途で判断する
- 既存ファイルの修正では、対象の言語・シェル・shebang・既存スタイルに従う。ユーザーがfishを使うことを理由にfish構文へ変更しない
- 新規のシェルスクリプトは、指定がなければ移植性のあるPOSIX shを優先し、必要な機能や実行環境に応じてbashなどを選ぶ。fishは明示的な指定、またはfish用の関数・設定など対象自体がfishである場合にのみ使用する
- CI設定・Makefile・package.jsonなどに埋め込むコマンドも、その実行環境のシェルに合わせる

## エージェントが実行するコマンド

- ツールの実行環境に合わせる。ユーザーの対話シェルに合わせてfish構文にする必要はない

# プラン実装の完遂ルール

- 承認済みプランの実装では、全項目の実装と検証が終わるまで作業を継続する
- 個別タスクの完了を、プラン全体の完了と取り違えない
- 各項目は完了条件を検証してから完了扱いにする
- 未完了項目が残っている状態で完了を報告しない
- ユーザー判断が必要な問題、権限不足、解消不能な外部依存以外では中断しない
- 大規模なプランは直列マイルストーンに分割し、各マイルストーンで実装・検証・レビュー・修正を行う
- 実装担当の完了後、親エージェントがプランと差分を照合し、最終検証を行う
- 最終報告には、実装済み項目、未完了項目、検証コマンドと結果、残存リスクを含める
